# Admin Creation Forms Update

This version adds consistent in-app modal forms for creating customers, branches, accounts, and cards.

## UI changes

- **Customers → Add New Customer** opens a styled form for customer details. Customer ID is optional; blank means use the backend's next-ID logic.
- **Branches → Add New Branch** opens a styled form for branch code, name, IFSC, phone, and address. Branch ID is optional.
- **Accounts → Create New Account** now uses the same modal styling and loads live branch/customer choices from the API.
- **Cards → Issue New Card** opens a staff-only form. Debit cards require an active linked account; credit cards require an active customer and a positive credit limit. Card expiry is selected in the form; the issue date and masked card identifier are generated by the backend.

The modal styling is shared through `frontend/shared/forms.css` and `frontend/shared/forms.js`.

## Backend change

A staff-only `POST /api/cards` endpoint was added. It creates either a debit or credit card transactionally and rejects inactive/missing account/customer selections. Customers may continue to view their own cards but cannot issue cards.

## Run

1. Extract this ZIP to a new folder.
2. Copy your working local `backend/.env` into the new project's `backend` folder. Do not share `.env` or secrets.
3. In PowerShell, run from `backend`:

   ```powershell
   npm install
   node server.js
   ```

4. Log in as Admin and test the Create Customer, Add Branch, Create Account, and Issue New Card buttons.

## Verification notes

- The API still requires the signed session token. Card creation is staff-only.
- The actual insert is verified only when tested against the user's PostgreSQL schema, because that database is local to the user.


## Banking action dialogs update

The current project also converts these actions to styled modal UI (no browser prompts/alerts for these flows):

- **Admin Loans**: New Application uses a validated modal with customer, branch, loan type, interest rate, principal, and tenure fields. Loan form lookup values come from PostgreSQL.
- **Loan actions**: Admin status changes use a status-select modal. Customer Payments opens an installment modal with due-date-aware payment actions; EMI opens a calculation details modal.
- **Accounts**: Deposit and Withdrawal use amount/method forms, submit to the existing procedures via the API, then refresh balances.
- **Transactions**: IMPS/NEFT/RTGS buttons toggle a selected transfer mode; 25%/50%/MAX use the selected account's live balance; the transfer form validates source, beneficiary, and amount; the reset button clears the form; Filter and Export CSV controls are wired.

Backend additions include the authenticated customer-safe `/api/loan-form-options` lookup endpoint, which returns only branch IDs/names and active loan interest rates.
