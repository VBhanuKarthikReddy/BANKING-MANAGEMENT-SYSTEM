# Final UI + QA Baseline V1

## Purpose
This baseline is the consolidated project after the functional integration phase and the first final UI consistency pass.

## UI changes
- One shared sidebar is generated by `frontend/shared/app-shell.js`.
- Legacy page sidebars and legacy navigation scripts are removed from module pages.
- Customer and Admin sidebars are role-aware.
- Customer/admin direct page guards remain in the shared shell.
- Shared Payments-style colors, cards, tables, inputs, buttons, modals, status badges, and spacing are applied through `app-shell.css` and `ui-polish.css`.
- Financial values use INR formatting through `formatMoney()`.
- Customer dashboard cards use loading placeholders until live API data is returned; zero is not shown as a fake loading state.
- Static mock transaction rows and dead `href="#"` links in the module UI were removed/replaced.
- List-count labels are updated from API data where supported.

## Static QA completed
- All JavaScript files pass `node --check`.
- Module pages contain exactly one shared shell script and one shared shell stylesheet.
- Legacy `<aside>` elements are removed from module pages.
- Legacy `navigation.js` and `session-ui.js` page includes are removed.
- No remaining `href="#"` values exist in module pages.
- The consolidated server contains routes for the integrated modules used by the frontend.

## Local QA still required
Because the real PostgreSQL instance and credentials belong to the development environment, final live-data verification must be run on the developer machine.

### Customer regression
Login as Customer `1001` with the current demo password and verify Dashboard, Accounts, Transactions, Loans, Cards, Fixed Deposits, Nominees, and Payments.

### Admin regression
Login as Admin with an active employee ID and verify Dashboard, Customers, Branches, Employees, Accounts, Transactions, Loans, Cards, Fixed Deposits, Nominees, Payments, Interest Rates, and Audit Logs.

### Security regression
Test wrong password, wrong role, direct access to staff pages as Customer, and direct staff-only API calls as Customer.

### Data regression
Verify that dashboard values, account balances, customer counts, transaction history, loans, cards, fixed deposits, payments, and audit logs match PostgreSQL.

## Next phase
After live QA passes, freeze this codebase and begin full project documentation: architecture, modules, schema, SQL objects, workflows, testing, screenshots, report, presentation, and viva material. The individual learning phase follows documentation.
